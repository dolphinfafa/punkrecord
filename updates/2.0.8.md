# v2.0.8 更新日志

**发布日期**：2026-08-31

> 小版本：微信通知升级为可交互的待办/审批入口，会议纪要生成补充会议日期上下文，并切换会议纪要模型到 Kimi K3。

---

## 会议记录

- **会议日期进入纪要上下文**：AI 生成会议纪要时会把会议标题、会议日期、参会人员和转写文稿一起传给模型。
- **不再误写“时间未注明”**：当会议日期字段有值时，模型会被明确要求把该日期作为会议时间/日期依据。
- **删除会议 500 修复**：删除带转写分段的会议时，后端先删除转写分段再删除会议主记录，避免 MySQL 外键约束导致失败。
- **模型切换**：开发和生产环境的会议纪要生成模型已通过 `.env` 切换为 Moonshot Kimi K3（`kimi-k3`）。真实 API key 仅保存在环境 `.env`，不会进入 Git。

## 微信通知与审批

- **微信入站消息处理**：用户可以在微信里发送“待办/审批/审核”等短指令，系统会查询真实待审批任务并逐条推送。
- **编号审批**：支持“通过 1”“拒绝 2 理由:xxx”“通过 <单号>”等回复，直接完成对应待办审批。
- **批量审批**：支持“全部通过”“都同意”“通过全部”“全部拒绝 理由:xxx”等指令，实时查询当前待我审批任务后批量执行。
- **请假审批同步**：通过微信审批关联请假待办时，会同步更新请假申请本身，避免待办和请假单状态不一致。
- **离线队列补发**：微信通道失效或消息服务不可达时，通知进入离线队列；用户下次发消息后立即补发积压通知。
- **通道保活提醒**：系统记录用户最近微信来信时间，距 24 小时通道过期不足 1 小时时推送一次保活提醒。
- **兜底对话防幻觉**：非指令消息走 LLM 兜底，但会注入真实待办/审批数量；具体事项不可确认时引导用户发送“待办”，不编造任务内容。

## 开发与部署

- **版本号更新**：后端默认 `APP_VERSION` 更新为 `2.0.8`，`backend/.env.example` 同步更新。
- **配置示例**：`backend/.env.example` 增加 Kimi K3 的 OpenAI 兼容配置占位，不包含真实 API key。
- **默认配置清理**：后端默认 LLM 地址/模型同步为 Moonshot Kimi K3，默认 API key 留空；`/ai` 路由只对旧 `gemini-*` 短模型名自动补 `gemini/` 前缀，`kimi-*` 等 OpenAI 兼容模型名保持原样。
- **数据库迁移**：新增 `20260818_0001_binding_inbound_tracking.py`，为 `wechat_notify_binding` 增加 `last_inbound_at` 和 `keepalive_notified_at`。
- **部署影响**：部署时需执行 Alembic upgrade、重启后端；本版本没有前端页面改动，不需要重新构建前端。
