# v2.0.8 更新日志

**发布日期**：2026-08-31（2026-09-29 补充发布）

> 小版本：微信通知升级为可交互的待办/审批入口，会议纪要补充会议日期上下文并切换至 GPT-5.6 Sol，MCP 增加待办编辑能力。

---

## 会议记录

- **会议日期进入纪要上下文**：AI 生成会议纪要时会把会议标题、会议日期、参会人员和转写文稿一起传给模型。
- **不再误写“时间未注明”**：当会议日期字段有值时，模型会被明确要求把该日期作为会议时间/日期依据。
- **删除会议 500 修复**：删除带转写分段的会议时，后端先删除转写分段再删除会议主记录，避免 MySQL 外键约束导致失败。
- **模型切换**：会议纪要及其他 OpenAI 兼容 LLM 调用默认切换为 GPT-5.6 Sol（`gpt-5.6-sol`），通过 `LITELLM_BASE_URL` / `LITELLM_MODEL` / `LITELLM_API_KEY` 配置。真实 API key 仅保存在环境 `.env`，不会进入 Git。

## MCP 服务

- **待办编辑工具**：新增 `update_todo`，可修改待办标题、描述、备注、优先级、起止时间、负责人、标签及项目关联信息。
- **复用权限与业务规则**：工具转发既有 `PATCH /api/v1/todo/{todo_id}`，访问控制、负责人调整、通知和项目进度联动与 Web 端保持一致。
- **工具清单**：MCP 工具总数由 38 更新为 39，`/api/v1/mcp-info` 可返回新工具说明和参数 Schema。

## 微信通知与审批

- **微信入站消息处理**：用户可以在微信里发送“待办/审批/审核”等短指令，系统会查询真实待审批任务并逐条推送。
- **编号审批**：支持“通过 1”“拒绝 2 理由:xxx”“通过 <单号>”等回复，直接完成对应待办审批。
- **批量审批**：支持“全部通过”“都同意”“通过全部”“全部拒绝 理由:xxx”等指令，实时查询当前待我审批任务后批量执行。
- **请假审批同步**：通过微信审批关联请假待办时，会同步更新请假申请本身，避免待办和请假单状态不一致。
- **离线队列补发**：微信通道失效或消息服务不可达时，通知进入离线队列；用户下次发消息后立即补发积压通知。
- **通道保活提醒**：系统记录用户最近微信来信时间，距 24 小时通道过期不足 1 小时时推送一次保活提醒。
- **兜底对话防幻觉**：非指令消息走 LLM 兜底，但会注入真实待办/审批数量；具体事项不可确认时引导用户发送“待办”，不编造任务内容。

## 开发与部署

- **版本号更新**：后端默认 `APP_VERSION` 更新为 `2.0.8`，`backend/.env.example` 同步更新。
- **配置示例**：`backend/.env.example` 更新为 GPT-5.6 Sol 的 OpenAI 兼容配置占位，不包含真实 API key。
- **默认模型配置**：后端默认 LLM 地址切换为 `https://l-llm.yios.cn/v1`，模型切换为 `gpt-5.6-sol`，默认 API key 保持为空。
- **开发登录修复**：开发服务器 PM2 后端固定使用 Conda `punkrecord` 的 Python 3.10，避免全局 Python 3.13 下 `passlib/bcrypt` 初始化异常导致正确密码登录仍返回 500。
- **启动脚本修复**：`scripts/start_backend.sh` 移除旧 `punk` 环境，直接使用 `/opt/miniconda3/envs/punkrecord/bin/python`。
- **数据库迁移**：新增 `20260818_0001_binding_inbound_tracking.py`，为 `wechat_notify_binding` 增加 `last_inbound_at` 和 `keepalive_notified_at`。
- **部署影响**：部署时需执行 Alembic upgrade、更新生产 `.env` 中的 `APP_VERSION` 和 `LITELLM_*`、重启后端；前端代码没有变化，但部署流程仍执行一次生产构建验证。
