# v2.0.9 更新日志

**发布日期**：2026-09-29

> 小版本：会议纪要切换至 GPT-5.6 Sol，MCP 增加待办编辑能力，并修复开发环境正确密码无法登录的问题。

---

## 会议记录与 AI

- **模型切换**：会议纪要及其他 OpenAI 兼容 LLM 调用默认切换为 GPT-5.6 Sol（`gpt-5.6-sol`）。
- **统一配置**：通过 `LITELLM_BASE_URL` / `LITELLM_MODEL` / `LITELLM_API_KEY` 配置模型，真实 API key 仅保存在各环境 `.env`，不会进入 Git。
- **网关验证**：模型列表和对话请求均返回 HTTP 200，会议纪要现有 SSE 流式解析格式保持兼容。

## MCP 服务

- **待办编辑工具**：新增 `update_todo`，支持修改标题、描述、备注、优先级、起止时间、负责人、标签及项目关联信息。
- **复用业务规则**：工具转发既有 `PATCH /api/v1/todo/{todo_id}`，访问控制、负责人调整、通知和项目进度联动与 Web 端一致。
- **工具清单**：MCP 工具总数由 38 更新为 39，`/api/v1/mcp-info` 已包含新工具说明和参数 Schema。

## 开发环境

- **登录修复**：开发服务器 PM2 后端固定使用 Conda `punkrecord` 的 Python 3.10，避免全局 Python 3.13 下 `passlib/bcrypt` 初始化异常导致登录接口返回 500。
- **启动脚本修复**：`scripts/start_backend.sh` 移除旧 `punk` 环境激活逻辑，直接使用 `/opt/miniconda3/envs/punkrecord/bin/python`。
- **错误定位**：确认账号与密码哈希本身正常；页面显示“用户名或密码错误”是对后端 500 的兜底文案，并非密码数据异常。

## 开发与部署

- **版本号更新**：后端默认 `APP_VERSION` 和 `backend/.env.example` 更新为 `2.0.9`。
- **配置示例**：默认 LLM 地址更新为 `https://l-llm.yios.cn/v1`，默认模型更新为 `gpt-5.6-sol`，模板不包含真实 API key。
- **部署影响**：无需新增数据库迁移；部署时更新环境 `.env`、构建前端并重启后端。
