# 2026-07-01 Milestone

## 会议音频转录完整性与时间轴修复

### 背景

用户反馈会议记录上传音频后，ASR 转写文本经常不全，且部分转录段文字与播放器音频片段对不上。诊断重点落在大文件切片与转录段时间偏移：旧逻辑按文件大小均分时长、`ffmpeg -ss` 放在输入前做快速 seek，并且切片输出被重编码但格式/扩展与 ASR 声明可能不一致，容易造成边界漏识别和时间轴漂移。

### 后端修复

- `backend/app/services/asr_service.py`：
  - 新增 content-type + 文件扩展双通道格式识别，避免浏览器上传 content-type 不准时误报格式。
  - 大文件或长音频触发切片：`>300MB` 或 `>25分钟`。
  - 切片统一输出 16k 单声道 mp3，并向 ASR 声明 `mp3`，保证文件内容、扩展名和 ASR format 一致。
  - `ffmpeg` 改为输入后 `-ss` 精确 seek，减少切片边界与原音频时间不一致。
  - 切片间保留 5 秒重叠，合并时按时间重叠 + 文本相似度去重，减少边界漏字又避免重复句子。
  - 合并后按 `start_time/end_time` 排序并重建全局 `segment_index`。
  - 单个切片返回空结果会记录 warning；所有切片都无内容时仍由 meeting API 标记 failed。
- `backend/app/api/meeting.py`：ASR 返回 `duration_seconds` 后写入 `meeting_record.duration_seconds`，列表/详情可显示真实音频时长。

### 前端修复

- `frontend/src/pages/meeting/MeetingDetailPage.jsx`：转录片段播放时间从 `segment.start_time || segment.start` 改为 `segment.start_time ?? segment.start ?? 0`，保留 `0` 秒合法值，避免首段播放定位异常。

### 测试

- 新增 `backend/tests/test_asr_service.py`：覆盖多切片合并偏移、重叠文本去重、空切片 warning。

| 前端 | `frontend/src/pages/meeting/MeetingDetailPage.jsx` |

## 财务交易作废删除 + Excel 导出修复

### 背景

用户反馈两个财务管理问题：作废交易只能恢复，缺少彻底删除入口；交易明细导出 Excel 报错，无法下载。

### 后端修复

- `backend/app/api/finance.py`：
  - 新增 `DELETE /api/v1/finance/transactions/{txn_id}`，仅允许删除 `voided=true` 的作废交易；正常交易会返回业务错误，要求先作废再删除，避免误删有效流水。
  - `GET /api/v1/finance/transactions/export` 新增 `status` 筛选，导出内容与当前列表状态筛选保持一致。
  - 导出响应 `Content-Disposition` 改为 `filename=transactions.xlsx` + `filename*=UTF-8''<urlencoded>`，避免中文文件名直接进入响应头导致编码错误。
  - 作废交易导出时状态列显示“作废”。

### 前端修复

- `frontend/src/api/finance.js`：新增 `deleteTransaction()`，导出接口透传 `status`。
- `frontend/src/pages/finance/TransactionListPage.jsx`：
  - 作废交易行在“恢复”旁新增“删除”按钮，删除前二次确认。
  - 导出逻辑按当前 axios 响应拦截器直接处理 `Blob`，不再读取 `res.data`，同时导出带上状态筛选。
  - Blob 错误响应会尝试解析 JSON 错误信息，便于定位导出失败原因。

### 测试

- 新增 `backend/tests/test_finance_transactions.py`：覆盖正常交易不可删除、作废交易可删除、导出响应头 ASCII-safe 且返回 xlsx 内容。

### 修改文件

| 类别 | 文件 |
|------|------|
| 后端 | `backend/app/api/finance.py` |
| 前端 | `frontend/src/api/finance.js`、`frontend/src/pages/finance/TransactionListPage.jsx` |
| 测试 | `backend/tests/test_finance_transactions.py` |
| 文档 | `.agent/workflows/backend-api.md`、`.agent/workflows/frontend.md`、`milestone/2026-07-01.md` |

## MCP 财务工具同步

### 背景

复查今天会议记录与财务管理更新对 MCP 服务的影响：会议转录修复只改变后端 ASR 处理和前端播放定位，不改变 MCP 现有会议工具契约；财务新增作废删除和状态筛选，需要同步 MCP 工具能力。

### 后端修复

- `backend/app/api/mcp_server.py`：
  - `list_transactions` 增加 `account_id`、`txn_direction`、`status`、`page` 筛选参数，支持通过 `status=voided` 查询作废交易。
  - 新增 `void_transaction(txn_id)`，转发 `POST /finance/transactions/{id}/void`。
  - 新增 `unvoid_transaction(txn_id)`，转发 `POST /finance/transactions/{id}/unvoid`。
  - 新增 `delete_voided_transaction(txn_id)`，转发 `DELETE /finance/transactions/{id}`，仅删除已作废交易。

### 验证

- `mcp.list_tools()` 返回 28 个工具，包含 `void_transaction`、`unvoid_transaction`、`delete_voided_transaction`。
- 运行中的 `/api/v1/mcp-info` 已返回 28 个工具，说明 dev 后端已加载新 MCP 定义。
