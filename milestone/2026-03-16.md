# 2026-03-16 Milestone

## 新增「企业大脑」和「会议记录」两大功能模块

### 1. 背景

PunkRecord 项目需要新增两个核心功能模块：
- **企业大脑**（Knowledge Base）：企业知识的统一存储和检索中心，支持文档上传、AI 自动分类、RAG 语义对话
- **会议记录**（Meeting）：音频上传、ASR 自动转写、说话人标注、AI 会议纪要生成，完成后可归档到企业大脑形成闭环

技术选型：AI 对话/Embedding 用 Gemini | 向量存储用 ChromaDB | ASR 用豆包（火山引擎）| 文档分类由 AI 自动生成

### 2. 数据模型

新增 6 张数据表：

**企业大脑（4 张表）**

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `kb_document` | 知识库文档主表 | title, file_name, stored_name, content_type, file_size, extracted_text, summary, tags(JSON), status(processing/ready/failed), chunk_count, uploaded_by, source_type, source_id |
| `kb_document_chunk` | 文档切片表 | document_id(FK), chunk_index, content, token_count, chromadb_id |
| `kb_conversation` | 对话会话表 | title, user_id(FK) |
| `kb_message` | 对话消息表 | conversation_id(FK), role(user/assistant), content, references(JSON), attached_document_id |

**会议记录（2 张表）**

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `meeting_record` | 会议主表 | title, audio_file_name, audio_stored_name, status(uploading/transcribing/transcribed/summarized/archived/failed), asr_task_id, speaker_mapping(JSON), summary, created_by, archived_document_id |
| `meeting_transcript_segment` | 转写分段表 | meeting_id(FK), segment_index, speaker_id, start_time, end_time, content |

### 5. 服务层

新增 6 个服务文件（`backend/app/services/`）：

| 文件 | 职责 |
|------|------|
| `document_parser.py` | 文本提取（PDF→PyPDF2, Word→python-docx, Excel→openpyxl, 图片→Gemini Vision）+ 文本切片 |
| `embedding_service.py` | Gemini Embedding API（text-embedding-004），支持单条和批量 |
| `vector_store.py` | ChromaDB 封装（嵌入式持久化），add/search/delete |
| `kb_pipeline.py` | 文档处理管线：存储→解析→切片→Embedding→ChromaDB→AI生成标签摘要 |
| `rag_service.py` | RAG 对话：Embedding查询→ChromaDB检索→拼接上下文→Gemini流式回答 |
| `asr_service.py` | 豆包 ASR 封装（app_key=7858270680）：提交音频→解析结果（含说话人分离） |

文档处理管线和 ASR 任务使用 `asyncio.ensure_future()` 异步执行，不引入 Celery。

### 8. 开发过程中的问题修复

| 问题 | 原因 | 修复 |
|------|------|------|
| chromadb 导入报错 `np.float_` | chromadb 0.4.x/0.5.0 与 NumPy 2.0 不兼容 | 升级到 chromadb 1.5.5 |
| 登录报错 `password cannot be longer than 72 bytes` | bcrypt 5.0.0 与 passlib 不兼容 | 降级 bcrypt 到 4.0.1 |
| 外键引用错误 `table 'user' not found` | User 模型表名是 `users`，外键写了 `user.id` | 修正为 `users.id` |
| `AtlasException` 参数顺序错误 | meeting.py 中写了 `AtlasException(400, "msg")` | 修正为 `AtlasException("msg")` |
| Pydantic 模型未序列化 | `success_response()` 接收 Pydantic 对象而非 dict | 添加 `.model_dump()` |
