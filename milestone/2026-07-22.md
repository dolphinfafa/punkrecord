# 2026-07-22 Milestone

## MCP 图片读取能力补齐（v2.0.6）

### 背景

用户反馈当前 MCP 服务在查看 Bug 和待办事项时，拿不到其中的图片信息。实际排查后确认：

- 待办图片存储在 `TodoItem.link.todo_images`，REST 层已返回基础元数据和相对下载路径，但 MCP 原样转发后没有公网可用 URL。
- Bug 配图不是待办图片，而是 `TodoItem.link.bug_images` 中保存的项目附件引用（`attachment_id`），需要走项目附件下载接口。
- 图片下载接口需要鉴权，不能把 Agent Token 拼进 URL；同时部分 MCP 客户端不方便再发带 Header 的 HTTP 下载请求。

### 后端实现

- `backend/app/api/mcp_server.py`
  - 新增 `_download_file()`：用调用 MCP 时的 `Authorization` 转发受保护文件下载，跟随对象存储重定向，返回 base64。
  - 新增公网 API URL 推导：
    - 优先从 `settings.MCP_PUBLIC_URL` 推导 `/api/v1` base。
    - 未配置时根据 `X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Forwarded-Prefix` 和当前请求路径推导。
    - 兼容生产 `https://punkrecord.yios.cn/api/v1/mcp` 与开发 `/punkrecord/api/v1/mcp` 子路径。
  - 待办图片补全：
    - `list_my_todos`
    - `get_todo`
    - `list_todo_images`
    - `create_todo`
    - `start_todo` / `submit_todo` / `block_todo` / `dismiss_todo`
    - `list_tasks_to_review` / `approve_todo` / `reject_todo`
  - Bug 配图补全：
    - `get_todo`
    - `list_my_todos`
    - `list_project_todos`
    - `list_tasks_to_review`
    - 任务创建与状态变更返回值
  - 图片元数据新增字段：
    - `api_download_url`
    - `download_url`
    - `requires_auth=true`
    - `auth_note`
  - 新增 MCP 工具：
    - `get_todo_image(todo_id, image_id)`：读取待办图片，返回 `{file_name, content_type, size, content_base64}`。
    - `get_bug_image(project_id, attachment_id)`：读取 Bug 配图项目附件，返回 `{file_name, content_type, size, content_base64}`。
