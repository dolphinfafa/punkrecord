# 2026-04-20 Milestone

## 通知调用全量保护 (v1.0.5)

### 1. 背景

生产环境中，待办事项拖动到"已完成"时偶发 500 错误（实际操作已成功，刷新后正常）。v1.0.4 已修复 `create_todo` 和 `update_todo` 中的通知调用，但遗漏了其余 6 处状态变更端点中的通知调用。

### 2. 问题分析

所有待办状态变更端点的流程：主操作 commit → 通知调用 → commit。当通知调用失败时（微信推送超时/NotificationLog 写入异常），第二次 commit 报错导致 500 响应，但主操作（状态变更）在第一次 commit 时已持久化。

### 3. 修复内容

对以下 6 处通知调用统一增加 try/except 包裹，失败时 rollback 但不影响主操作响应：

| 函数 | 场景 | 通知对象 |
|------|------|----------|
| `submit_todo` | 任务提交完成 | 创建人 |
| `approve_todo` | 审核通过 | 负责人 |
| `reject_todo` | 审核驳回 | 负责人 |
| `updateStatus`（submit 分支） | 状态变更为上报完成 | 创建人 |
| `block_todo` | 标记阻塞 | 创建人 |
| `updateStatus`（reopen 分支） | 重新打开 | 负责人 |

加上 v1.0.4 已修复的 `create_todo` 和 `update_todo`，共 8 处通知调用全部覆盖。
