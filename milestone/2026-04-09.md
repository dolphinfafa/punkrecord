# 2026-04-09 Milestone

## Bug 描述同步 + 团队任务逻辑优化 + 请假半天精度 (v1.0.4)

### 1. 背景

本次迭代包含三项改进：修复 Bug 编辑后待办事项描述不同步的问题、优化团队任务显示逻辑并新增审核人过滤器、将请假申请的计算精度从整天细化到半天（0.5 天）。

### 2. Bug 编辑同步 TodoItem 描述

#### 2.1 问题

- Bug 创建时会正确组合描述（`【实际结果】...【期望结果】...【复现步骤】...【备注】...`）到关联 TodoItem
- Bug 编辑后，修改的内容未同步到 TodoItem 的描述字段

#### 2.2 修复

- `updateBug()` 新增与 `createBug()` 一致的描述组合逻辑，编辑后自动重新拼接所有字段
- `startEditBug()` 修正备注回填：从 `link.notes` 或解析旧描述中提取纯备注文本，不再将完整组合字符串填入备注输入框
- `createBug()` 在 link 中新增 `notes` 字段存储备注原文，方便后续编辑时准确提取

### 3. 团队任务显示逻辑优化

#### 3.1 后端查询条件变更

- **旧逻辑**：`(creator==me AND assignee!=me) OR (reviewed_by==me)`
- **新逻辑**：`assignee_user_id != current_user`，即显示所有负责人非本人的任务
- 新增 `reviewed_by_user_id` 可选查询参数，支持按审核人过滤

#### 3.2 前端审核人过滤器

- 团队任务视图新增"审核人"下拉过滤器，位于"负责人"过滤器右侧
- 默认值为当前用户（显示审核人是自己的任务），可切换为"全部审核人"
- 切换到团队任务 tab 时自动重置审核人过滤器为当前用户
- 过滤器为服务端过滤，通过 `reviewed_by_user_id` 参数传递

### 4. 请假半天精度

#### 4.1 工作时间定义

| 时段 | 时间 | 算法 |
|------|------|------|
| 上午 | 10:00 - 12:00 | 0.5 天 |
| 午休 | 12:00 - 14:00 | 不计入 |
| 下午 | 14:00 - 19:00 | 0.5 天 |
| 非工作日 | 周六/周日 | 跳过 |

#### 4.2 后端 `_calc_leave_days()` 重写

- 返回类型从 `int` 改为 `float`
- 遍历日期范围内每个工作日，判断请假时段与上午/下午的重叠
- 每个重叠的半天计 0.5 天，最低 0.5 天
- 请假描述增加"上午/下午"标注和计算天数显示

#### 4.3 前端表单改造

- `datetime-local` 输入改为 `date` 日期选择器 + 上午/下午下拉框
- 开始时间：上午→10:00，下午→14:00
- 结束时间：上午→12:00，下午→19:00
- 提交前校验结束时间晚于开始时间

### 6. 后续修复（同日第二轮）

#### 6.1 待办事项 500 报错

- 新建/修改任务后通知发送失败导致接口返回 500（操作本身已成功）
- 修复：通知代码（`_notify_user`/`_notify_manager`）用 try/except 包裹，失败时 rollback，不影响主操作响应

#### 6.2 审核人过滤不准

- 原因 1：`reviewed_by_user_id` 查询参数为 string，数据库字段为 UUID，直接比较无法匹配
- 原因 2：大量任务未显式设置 `reviewed_by_user_id`（为 None），但创建人是隐含审核人
- 修复：参数转 UUID 后比较；增加 fallback 逻辑 — 当 `reviewed_by_user_id` 为空时，匹配 `creator_user_id`

#### 6.3 工作台待审批统计范围

- 问题：待审批数字统计了所有上报完成的任务，不限审核人
- 修复：前端 API 调用增加 `reviewed_by_user_id=user.id` 参数，仅统计审核人为本人的任务

#### 6.4 弹窗宽度修复

- 问题：`WeChatNotifyPage.css` 中 `.modal-content { width: 400px }` 全局污染了 TodoModal 的 800px 设置
- 修复：重命名为 `.wechat-modal-content`，避免全局样式冲突
- TodoModal 和 TodoDetailModal 的 max-width 统一为 800px
