# 2026-04-26 Milestone

## Bug 删除 500 修复 (v1.0.7)

### 1. 背景

生产环境中删除 Bug 时报 500 错误。

### 2. 问题排查

通过在生产环境模拟删除流程，定位到具体报错：

```
OperationalError: Unknown column 'notification_log.recipient_user_id'
```

**根因**：`_delete_todo_and_notifications()` 删除 Bug 前会查询并清理关联的 `NotificationLog` 记录。微信通知功能新增了 `NotificationLog` 模型字段（`recipient_user_id` 等），但生产数据库未执行迁移，导致 SELECT 语句引用了不存在的列。

### 3. 修复

在 `_delete_todo_and_notifications()`（project.py）中，通知记录的查询和删除用 try/except 包裹，失败时 rollback 但不阻塞 todo 本身的删除。与之前 v1.0.5 中对状态变更端点通知调用的保护思路一致。

| 文件 | 修改内容 |
|------|----------|
| `backend/app/api/project.py` | `_delete_todo_and_notifications` 通知查询/删除增加 try/except + rollback |
| `.agent/workflows/backend-api.md` | 通知安全规则补充删除场景说明 |
