# 2026-08-17 Milestone

## 会议记录转写稿编辑增强（v2.0.7）

### 背景

用户反馈会议记录在上传音频或文稿后，识别出来的转写稿需要更强的人工编辑能力：

- 修改转写文本后点击“保存修改”出现 422。
- 需要在转写稿中新增讲话人。
- 需要支持在指定位置插入行。
- 参会人员不应再单独维护，应跟修改后的转写文本中的说话人保持一致。

### 后端实现

- `backend/app/schemas/meeting.py`
  - `TranscriptSegmentUpdate.id` 从必填 UUID 改为可选 UUID/字符串，兼容前端新插入行的临时 ID。
  - 新增 `start_time`、`end_time`、`segment_index` 字段，支持完整分段列表保存。
  - `TranscriptBatchUpdate` 新增 `replace` 标记。

- `backend/app/api/meeting.py`
  - 新增 `_load_transcript_segments()`、`_serialize_transcript_segments()`、`_coerce_uuid()`。
  - 新增 `_replace_transcript_segments()`：`replace=true` 时按提交的完整 `segments` 列表整体替换，支持新增、插入、删除和重排分段。
  - 新增 `_attendee_names_from_speakers()`：按分段顺序收集实际使用的 `speaker_id`，结合 `speaker_mapping` 去重生成参会人员。
  - `PATCH /meeting/records/{id}/transcript`
    - 兼容旧批量更新模式。
    - 新增完整替换模式，保存后返回最新分段列表和会议详情。
    - 修复前端传临时行 ID 导致 422 的问题。
    - 保存后自动同步 `MeetingRecord.attendees`。
  - `PUT /meeting/records/{id}/speakers`
    - 更新说话人映射后自动同步参会人员。
  - `POST /meeting/records/{id}/upload-transcript`
    - 导入文稿后自动按转写分段和 speaker 映射生成参会人员。

### 前端实现

- `frontend/src/pages/meeting/MeetingDetailPage.jsx`
  - 转写文本编辑改为直接修改本地分段草稿。
  - 新增“新增讲话人”按钮，自动生成 `speaker_N` 并默认显示为“讲话人N”。
  - 新增“添加行”按钮。
  - 每个转写分段行新增：
    - 上方插入
    - 下方插入
    - 删除此行
  - 每行 speaker 可继续通过下拉切换。
  - 保存时统一提交 `replace=true` 的完整分段列表。
  - 保存后用后端返回的最新分段和会议详情刷新页面状态。
  - 移除无音频会议的手动参会人员编辑区。
  - API 422 校验错误会显示更具体的后端错误信息。

- `frontend/src/pages/meeting/MeetingDetailPage.css`
  - 新增 speaker 添加按钮样式。
  - 新增转写行插入/删除图标按钮样式。
  - 移动端下行级操作按钮自动换行，避免挤压 speaker 和时间标签。
