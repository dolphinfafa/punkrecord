# 2026-04-22 Milestone

## ASR 大文件切片转写 + 空结果 Bug 修复

### 1. 背景

生产环境上传 385MB（210 分钟）会议音频后，显示状态为"已转录"但转录文本为空。排查发现 base64 编码后 ~513MB 超出豆包 ASR API 限制，触发 `httpx.ReadError`，且该异常的 `str()` 为空字符串，绕过了 error 检查，0 segments 仍被标为 `transcribed`。

### 2. 问题复现

在开发环境从生产服务器复制 385MB 音频文件，直接调用 ASR 服务复现：
- `httpx.ReadError` 异常 → `str(e)` 为空 → `if result.get("error"):` 为 falsy → 不进入失败分支
- 0 segments → 状态标为 `transcribed`

### 3. 方案评估

| 方案 | 说话人识别 | 改动量 | 结论 |
|------|-----------|--------|------|
| URL 回调 | 完整 | 小，但需 Nginx 配置 | 备选 |
| 音频切片 | 每片独立，需人工合并 | 中等，后端改动 | **采用** |

选择切片方案原因：不依赖外部 URL 可达性，切片后说话人通过人工改名合并，AI 纪要自然识别同名为同一人。

### 4. 实现

#### 4.1 切片逻辑（`asr_service.py`）

- 新增 `_split_audio()`：检测文件 > 300MB 时用 ffmpeg 按时间等分切片（重编码为 mp3）
- 阈值 300MB 而非 400MB：考虑 base64 膨胀 33%（300MB → ~400MB），确保在 API 限制内
- 新增 `_get_audio_duration()`：ffprobe 获取音频总时长
- 重构 `submit_asr_task()` 为入口函数：自动切片 → 逐片调用 `_submit_single_chunk()` → 合并结果
- 新增 `_cleanup_chunks()`：清理临时切片文件

#### 4.2 Speaker ID 命名规则

- 单片（≤ 300MB）：`speaker_0`、`speaker_1`（不加前缀，向后兼容）
- 多片：`chunk1_speaker_0`、`chunk2_speaker_0`（按片编号加前缀）
- 用户在前端将不同 chunk 的说话人改为同一名字 → AI 纪要自动视为同一人

#### 4.3 结果合并

- `start_time`/`end_time` 加上该片的时间偏移量
- `segment_index` 全局递增（跨片连续）
- 任一片失败则整体返回 error

#### 4.4 Bug 修复

- `str(e) or type(e).__name__`：确保 error 字段非空字符串
- 静音检测（20000003）返回时现在正确设置 `error` 字段
- `_run_asr()`：ASR 返回 0 segments 时标记 `FAILED` 而非 `TRANSCRIBED`
- 每片 ASR 超时从 10 分钟调整为 20 分钟
