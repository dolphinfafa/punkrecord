## 批量创建员工账号

### 1. 背景

为黄金梅丽号部门批量创建 4 个员工账号，并配置组织架构关系（上下级、部门、职位）。要求新账号首次登录跳过填表流程，直接进入主页。

### 2. 创建的账号

| 小泽 | xiaoze | xiaoze123 | 前端工程师 | 杨喆 | 黄金梅丽号 |
| 李辰欣 | lichenxin | lichenxin123 | 实习生 | 殷萄 | 黄金梅丽号 |
| 小雪 | xiaoxue | xiaoxue123 | 测试员 | 殷萄 | 黄金梅丽号 |

### 3. 实现方式

编写独立种子脚本 `backend/create_employees.py`，逻辑：

1. 查找或创建部门「黄金梅丽号」（`org_unit` 表）
2. 查找或创建 4 个职位：产品经理、前端工程师、实习生、测试员（`job_title` 表）
3. 查找上级用户「杨喆」（`users` 表）
4. 创建 4 个用户，设置 `profile_completed=True` + `must_change_password=False` 跳过首次登录填表
5. 为所有用户分配 `employee` 角色
6. 先创建殷萄，再将其设为李辰欣和小雪的上级

脚本具备幂等性：重复运行时检测已存在的数据会跳过，不会重复创建。

### 4. 首次登录免填表机制

系统通过两个字段控制首次登录行为：
- `profile_completed`：默认 `False`，为 `False` 时跳转到填表页
- `must_change_password`：默认 `True`，为 `True` 时跳转到改密页

本次创建的账号将两者分别设为 `True` 和 `False`，登录后直接进入主页。

### 5. 附带数据变更

- `org_unit` 表：新增「黄金梅丽号」部门（如不存在）
- `job_title` 表：新增 4 个职位（产品经理、前端工程师、实习生、测试员）
- `users` 表：新增 4 条用户记录
- `user_role` 表：新增 4 条角色关联（均为 employee 角色，scope=global）

## 修复 RBAC 权限控制不生效的 Bug

### 1. 问题描述

管理员在后台为不同职位分配了不同权限，但前端仍然显示所有模块且均可操作，权限配置形同虚设。

### 2. 根因分析

共发现 5 层问题：

| 层级 | 问题 | 影响 |
|------|------|------|
| 后端配置 | `ENFORCE_RBAC=False`，所有权限检查被跳过 | API 层无权限拦截 |
| 后端数据 | 权限码不匹配：端点用 `iam.read`，DB 中是 `iam.user.read` | 即使开启 RBAC 也会 403 |
| 后端 API | `/auth/me` 不返回权限数据 | 前端无法获知用户有哪些权限 |
| 前端菜单 | `Sidebar.jsx` 菜单硬编码，不做任何权限过滤 | 所有模块始终可见 |
| 前端路由 | `App.jsx` 路由无权限守卫 | 直接访问 URL 也不拦截 |

### 3. 修复方案

#### 3.1 后端 — 统一权限码

将数据库中 16 个细粒度权限码（如 `iam.user.read`、`finance.account.read`）合并为 10 个模块级权限码，与 `require_permission()` 装饰器中使用的一致：

| 模块 | 权限码 |
|------|--------|
| IAM | `iam.read`, `iam.write` |
| Todo | `todo.read`, `todo.write` |
| Contract | `contract.read`, `contract.write` |
| Project | `project.read`, `project.write` |
| Finance | `finance.read`, `finance.write` |

编写一次性迁移脚本 `fix_permissions.py`，自动合并旧权限码并迁移 `job_title_permission` 和 `role_permission` 中的关联记录。同步更新 `init_db.py` 和 `create_admin.py` 中的 seed 数据。

#### 3.2 后端 — `/auth/me` 返回权限

在 `core/auth.py` 新增 `get_user_permissions()` 函数，合并角色权限 + 职位权限取并集（admin 角色自动获得全部权限）。`/auth/me` 响应新增 `permissions` 字段。

#### 3.3 后端 — 开启 ENFORCE_RBAC

`.env` 新增 `ENFORCE_RBAC=true`，后端 `require_permission()` 正式校验权限，无权限返回 403。

#### 3.4 前端 — AuthContext 存储权限

`AuthContext.jsx` 在登录和 `/auth/me` 刷新时存储 `permissions` 数组，暴露 `hasPermission()` 和 `hasAnyPermission()` 方法供组件使用。

#### 3.5 前端 — Sidebar 权限过滤

每个菜单项增加 `permission` 字段，`Sidebar` 通过 `hasPermission()` 过滤，用户只能看到有权限的模块。工作台始终可见。

#### 3.6 前端 — 路由权限守卫

`App.jsx` 新增 `PermissionRoute` 组件，包裹各模块路由。无权限时显示 403 提示页面，防止通过 URL 直接访问。

### 4. 验证结果

- admin 用户：拿到全部 10 个权限，所有模块可见
- 殷萄（产品经理）：仅拿到职位分配的 4 个权限（`project.read/write` + `todo.read/write`），只能看到对应模块
- 前端构建通过，后端导入正常
