# 2026-06-05 Milestone

## punkrecord-skill 多项修复 + 会议纪要提示词交互修复

### 1. 背景

用户在使用 `punkrecord` Agent Skill（AI Agent 通过 Agent Token 调用 API）与会议纪要功能时发现多个问题。本次在 `dev` 分支集中修复（未动 main）。先用两个不同权限的测试 Token（`zheyang` 全权限 / `xiaoze` 低权限）实测复现并定位根因，逐项修复后端 + 文档，并全部 curl 端到端验证通过。

### 2. 后端修复

#### 2.1 阻塞/忽略任务参数位置（todo.py）

`block_todo` / `dismiss_todo` 原把 `blocked_reason`/`dismiss_reason` 声明为裸 `str` → FastAPI 视为 **query 参数**，导致 Agent 用 `-d '{...}'`（body）多次失败重试。
- 改为从**请求体**接收（新增 `TodoBlockRequest`/`TodoDismissRequest` schema），兼容 query。
- block 缺原因返回友好 400；dismiss 原因可选。

#### 2.2 创建任务支持项目关联 + dev_type（todo.py）

`create_todo` 增强，便于一次创建项目任务，免去多轮对话：
- `link.project_id` 或 `link.project_name`：解析项目 → 设 `source_type=PROJECT_TASK`、`source_id=project_id`，出现在项目任务列表；`project_name` 精确匹配，同名多个报错要求改用 id；关联后调用 `sync_project_progress` 同步进度。
- `link.dev_type`：校验 `VALID_DEV_TYPES`（dev_backend/dev_frontend/dev_ui/dev_product/other），写入 `tags` 与 `link.dev_type`，与项目页任务一致。

#### 2.3 任务图片查看接口（todo.py）

原仅有按 `image_id` 下载，Agent 无便捷入口。新增：
- `GET /todo/{id}/images`：列出任务全部图片（`id`/`file_name`/`content_type`/`download_path`）。
- `GET /todo/images?todo_id=|title=`：按任务 id 或**任务名**定位图片，同名多个返回候选列表。
- 新增 `_serialize_todo_images()` 辅助函数（剥离内部 `stored_name`，附下载路径）。
- 注意路由顺序：字面量 `/todo/images` 声明在 `/todo/{todo_id}` 之前，避免被 UUID 路径参数捕获。

#### 2.4 合同编号可选 + 自动生成（contract.py / schemas/contract.py）

`ContractCreate.contract_no` 改为 `Optional`，`create_contract` 缺省时自动生成 `CNT-<毫秒时间戳>-<2字节随机>`，与前端页面 `CNT-<Date.now()>` 规则一致，避免 Agent 自造编号与页面不一致或漏传报错。

#### 2.5 项目阶段状态强制顺序（project.py）

`update_stage_status` 原不校验顺序（可在 1 阶段未完成时直接更新 4 阶段）。
- 当目标 `status` 为 `in_progress`/`done` 时，校验所有 `sequence_no` 更小的前序阶段必须为 `done` 或 `skipped`，否则 400 并指明第一个未完成阶段名。
- 回退/阻塞/显式跳过（`not_started`/`blocked`/`skipped`）不受限。

#### 2.6 知识库语义检索/RAG 对话报错友好化（kb.py / rag_service.py）

根因：嵌入与对话直连 Google 且 `GEMINI_API_KEY` 未配置、ChromaDB 向量库为空。本轮按约定**仅做报错友好化**（不迁移 LiteLLM）：
- `semantic_search` 捕获 `RuntimeError`，返回 `{results:[], available:false, message:...}`，不再 500 ExceptionGroup。
- `rag_chat_stream` 检索失败时 yield 友好 SSE error 并返回。
- 修正 skill 文档：`/kb/chat` body 字段是 **`message`** 而非 `query`。

#### 2.7 权限审计（问题1：读放开、写拦截）

确认 project/contract/finance 三模块所有写操作均已正确 `require_permission("*.write")`，仅 export 导出类用 `get_current_user`（合理）；列表读接口对任意 Token 开放。结论：**无需改代码**，仅文档化权限模型。

### 2.8 侧边栏待办角标计数接口（todo.py）

新增 `GET /api/v1/todo/badge-counts`，返回侧边栏两个角标计数（`func.count` 精确高效）：
- `my_active`：我的任务中 `open`（未开始）+ `in_progress`（进行中）总和。
- `team_pending_review`：团队任务中待我审核的 `pending_review`（审核人是我，或审核人未设置且由我创建的隐含情形，与团队视图过滤一致）。

### 3. 前端修复

#### 待办角标：侧边栏 + 页内标签（Sidebar.jsx/css、TodoPage.jsx/css、api/todo.js）

两处复用同一接口 `GET /todo/badge-counts`，展示两个角标：蓝=我的未开始+进行中（`my_active`），红=团队待我审核（`team_pending_review`），仅 >0 时显示。
- **侧边栏**："待办事项"导航项右侧；挂载/路由切换拉取 + 45s 轮询；折叠态用红点提示。
- **待办页内**："我的任务/团队任务"切换标签右侧；计数在每次任务列表刷新（含开始/提交/审核等操作后）同步更新。

#### 会议纪要：选预设不再覆盖自定义提示词（MeetingDetailPage.jsx）

原逻辑预设与自定义互相清空：输入自定义内容后改选预设，自定义被清空。
- 第一版改为预设填入可编辑框（覆盖）。
- 按用户进一步反馈最终改为**追加**：选预设时把预设文案追加到自定义框已有内容之后（两部分共存，提交合并为 `prompt`），切换预设自动剥离上一次追加段以避免累积。
