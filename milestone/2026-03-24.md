# 2026-03-24 Milestone

## 待办事项审核流程修复与文档同步

### 1. 背景

QA 测试发现待办事项的审核流程存在多处问题：审核员字段未正确显示、审核权限判断逻辑不对、请假审批与 TodoItem 状态不联动、团队任务看板数据消失等。同时 project-overview.md 文档与实际代码存在 13 处不一致。

### 2. 修复内容

#### submit_todo 自指派判断修复

- **问题**：请假待办的 `creator == assignee`（都是申请人），submit 时走了自指派分支，`reviewed_by_user_id` 被覆写为申请人自己
- **修复**：自指派判断增加 `not todo.reviewed_by_user_id` 条件，有审核员的任务不走自动完成分支

#### 审核员字段显示修复

- **问题**：后端 `TodoResponse` 没有 `reviewer_name` 字段，`_enrich_todo` 只解析了 assignee/creator 名字；前端用 `creator_name` 代替审核员显示
- **修复**：
  - `TodoResponse` schema 新增 `reviewer_name`
  - `_enrich_todo` 根据 `reviewed_by_user_id` 查询并填充 `reviewer_name`
  - `TodoDetailModal` 优先显示 `reviewer_name`

#### 审核权限逻辑修复（后端）

- **问题**：`approve_todo` 和 `reject_todo` 检查 `creator_user_id != current_user.id`，但审核权限应归审核员
- **修复**：改为 `reviewer_id = todo.reviewed_by_user_id or todo.creator_user_id`，审核员优先，creator 为 fallback

#### 审核权限逻辑修复（前端看板拖拽）

- **问题**：看板拖拽到 done 列的前端权限检查只检查了 isManager/assignee/creator，缺少 `reviewed_by_user_id`
- **修复**：权限检查增加 `todo.reviewed_by_user_id === user?.id` 条件

#### TodoItem 审核联动请假状态

- **问题**：通过 TodoItem 审核通过请假待办后，`LeaveRequest` 表中的请假申请状态不更新
- **修复**：
  - `approve_todo`：`APPROVAL_STEP` 类型审核通过时，联动更新 `LeaveRequest` 为 `APPROVED`，扣减假期余额
  - `reject_todo`：`APPROVAL_STEP` 类型退回时，联动更新 `LeaveRequest` 为 `REJECTED`

#### 团队任务看板数据消失

- **问题**：团队任务加载后几秒数据消失
- **修复**：移除 `onClose` 中的 `fetchTodos()` 调用，避免关闭弹窗触发异步请求竞态覆盖数据
