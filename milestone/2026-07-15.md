# 2026-07-15 Milestone

## 会议文稿讲话人解析修复

### 背景

用户在开发环境创建会议记录 `测试文稿` 并上传录音文稿后，转写结果没有按文稿中的讲话人区分。排查发现文稿解析后的文本格式不是 `讲话人1：内容`，而是：

```text
讲话人1  00:20
你是磊哥吗？
讲话人2  00:23
首先，我已经完成剪映的检测并且正在测试效果。
```

旧解析器只识别“讲话人 + 冒号 + 内容”，因此将整篇文稿作为单个 `speaker_1` 分段。

### 后端实现

- `backend/app/api/meeting.py`
  - 扩展 `SPEAKER_LINE_RE`，支持 `讲话人1  00:20` 这类“讲话人 + 时间”的行。
  - 新增 `SPEAKER_HEADER_RE`，支持只有 `讲话人1` 的独立标题行。
  - `_parse_transcript_text()` 新增 `open_segment()` 统一打开分段。
  - 对“讲话人/时间行后下一行才是正文”的文稿格式，自动把后续正文归入对应 speaker。
  - 保留无说话人标签文稿的兜底逻辑。
- `backend/tests/test_meeting_transcript_import.py`
  - 新增 `test_parse_transcript_text_speaker_header_time_next_line_content`。
  - 覆盖 `讲话人1  00:20` + 下一行正文格式。

### 开发库修复

- 已对开发库会议 `测试文稿`（`91f688ed-035d-48d8-bd2e-e3a1b03d0ad1`）按新解析器重新拆分：
  - 原结果：1 个分段，`speaker_1`
  - 新结果：16 个分段，4 个讲话人
  - `speaker_mapping`：`讲话人1`、`讲话人2`、`讲话人3`、`讲话人4`

## 开发环境 `/punkrecord/` 白屏修复

### 背景

用户访问 `http://14.103.229.153:15173/punkrecord/` 看到白屏。排查确认前端资源加载正常，但控制台报：

```text
No routes matched location "/punkrecord/"
```

根因是此前为生产根域名部署将 Vite 默认 `base` 调整为 `/`，开发环境仍通过 `/punkrecord/` 子路径访问，React Router 的 basename 不匹配。

### 前端与脚本修复

- `frontend/src/App.jsx`
  - 新增 `getRouterBasename()`。
  - 当当前路径为 `/punkrecord` 或 `/punkrecord/...` 时，自动使用 `/punkrecord` 作为 Router basename。
  - 生产根域名仍使用 `/`。
- `dev.sh`
  - 前端启动命令改为显式设置 `VITE_BASE=/punkrecord/`：

```bash
env VITE_BASE=/punkrecord/ npx vite --host 0.0.0.0 --port 15173
```

### 开发环境验证

- 已重启开发前端 15173。
- Playwright 访问 `http://14.103.229.153:15173/punkrecord/`：
  - 自动跳转到 `/punkrecord/login`
  - 登录页正常渲染
  - 控制台无错误
