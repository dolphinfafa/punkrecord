# 2026-03-18 Milestone

## 会议记录模块 5 项优化

### 1. 背景

会议记录模块基础功能（上传音频 → ASR 转录 → 编辑文稿 → AI 总结 → 归档到企业大脑）已完成。用户提出 5 项优化需求，提升会议记录的实用性和搜索能力。

### 2. 优化内容

#### 优化 1：上传时增加会议日期

- MeetingRecord 模型新增 `meeting_date` 字段（DATE 类型，默认今天）
- 上传弹窗新增日期选择器，默认选中当天
- 列表页新增「会议日期」列
- 详情页 header 显示会议日期

#### 优化 2：单条转录文本可调整说话人

- TranscriptSegmentUpdate schema 新增 `speaker_id` 可选字段
- 后端 update_transcript 端点支持同时更新 speaker_id
- 前端每条 segment 的 speaker badge 可点击，弹出下拉框选择其他已有 speaker
- 保存时将 speaker_id 变更与文本修改一并提交

#### 优化 3：总结时可选提示词

- SummarizeRequest 已有 `prompt` 字段，前端新增预设提示词选择器（默认/早会/周会/复盘/头脑风暴/简洁要点）
- 支持自定义 textarea 输入提示词，覆盖预设
- 后端将自定义 prompt 追加到默认 system_prompt

#### 优化 4：参会人员存入数据库

- MeetingRecord 模型新增 `attendees` 字段（JSON 类型）
- 总结完成后自动从 speaker_mapping 提取非空姓名存入 attendees
- 列表页标题下方副文本显示参会人
- 列表页新增搜索框，支持搜索标题、参会人和日期
- 详情页 header 显示参会人员列表

#### 优化 5：引用上次会议上下文

- SummarizeRequest 新增 `previous_meeting_id` 可选字段
- 后端获取上次会议 summary 拼入 LLM prompt 作为对比上下文
- 前端加载已总结/已归档的历史会议列表（排除当前）
- summary section 增加可搜索的「引用上次会议」下拉组件，支持按短 ID / 标题 / 日期 / 参会人筛选

### 3. 数据库变更

```sql
ALTER TABLE meeting_record ADD COLUMN meeting_date DATE NULL, ADD COLUMN attendees JSON NULL;
```

已在 punkrecord_dev 数据库执行。

### 5. 后续修复

#### 引用上次会议搜索增强

- **列表页**：新增会议 ID 列，显示 UUID 前 8 位（等宽字体，hover 查看完整 ID）
- **详情页**：「引用上次会议」从普通 `<select>` 改为可搜索的自定义下拉组件，支持按短 ID / 标题 / 日期 / 参会人模糊过滤

#### 列表搜索框修复

- **问题**：`cast(attendees, String).ilike` 在 MySQL 上搜索 JSON 列不可靠，且未支持按日期搜索
- **修复**：改用 MySQL 原生 `JSON_SEARCH(attendees, 'one', '%keyword%')` 搜索参会人，新增 `cast(meeting_date, String).ilike` 支持按日期搜索

#### 会议 ID 列选中文本误触发跳转

- **问题**：列表页会议 ID 列选中文本后松开鼠标，click 事件冒泡到 `<tr>` 的 `onClick`，导致跳转到详情页
- **修复**：ID 列 `<td>` 添加 `onClick={e => e.stopPropagation()}`，CSS 添加 `user-select: text; cursor: text`

### 风险等级: low

- 所有修改限于会议记录模块，不影响其他功能
- 数据库新增字段均为 NULL 允许，不影响已有数据
- summarize 接口改为接受 JSON body，原有无 body 调用仍兼容（body 为 Optional）
