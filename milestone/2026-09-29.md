## 开发环境登录修复

### 问题

- 开发环境使用正确账号密码登录时，页面显示“用户名或密码错误”。
- 数据库账号状态和密码哈希均正常，直接密码匹配成功。

### 根因

- PM2 后端原先通过 PATH 中的 `uvicorn` 启动，实际落到全局 Python 3.13，而不是项目要求的 Conda `punkrecord` Python 3.10。
- 全局环境中的 `passlib/bcrypt` 组合在密码校验初始化阶段抛出 bcrypt 72 字节限制异常，登录接口实际返回 HTTP 500。
- 前端将未识别的服务端异常兜底显示为“用户名或密码错误”，掩盖了真实错误。

### 修复

- PM2 的 `punkrecord-backend` 改为直接使用 `/opt/miniconda3/envs/punkrecord/bin/python -m uvicorn`。
- 更新 `scripts/start_backend.sh`，移除旧 `punk` 环境激活逻辑，固定使用 `punkrecord` 解释器。
- 保存 PM2 当前进程列表，确保进程恢复后仍使用正确解释器。
- 更新项目行动纲领和运行文档，明确 Python 环境与敏感信息管理规则。

### 验证

- `GET /health`：HTTP 200。
- `POST /api/v1/auth/login`：HTTP 200。
- 携带登录 Token 请求 `GET /api/v1/auth/me`：HTTP 200，返回预期账号。
- 通过前端 Vite `/punkrecord/api/v1/auth/login` 代理登录：HTTP 200。
- 最新后端日志无新的 bcrypt 登录异常。
