## 合同附件管理

### 背景

用户提出合同管理需要支持上传附件，一个合同可包含多个 PDF 或图片附件，并且附件需要可查看。

### 后端实现

- `backend/app/api/contract.py`
  - 新增合同附件 REST 接口：
    - `GET /api/v1/contract/contracts/{contract_id}/attachments`
    - `POST /api/v1/contract/contracts/{contract_id}/attachments`
    - `GET /api/v1/contract/contracts/{contract_id}/attachments/{attachment_id}/view`
    - `GET /api/v1/contract/contracts/{contract_id}/attachments/{attachment_id}/download`
    - `DELETE /api/v1/contract/contracts/{contract_id}/attachments/{attachment_id}`
  - 限制附件类型为 PDF 和图片，单文件最大 20MB。
  - 文件存储在 `contract-attachments`，附件元数据写入 `contract.attachments` JSON。
- `backend/app/schemas/contract.py`
  - 新增 `ContractAttachmentResponse`。
  - `ContractResponse.attachments` 增加兼容性规范化。
- `backend/db_migrations/versions/20260708_0001_contract_attachments.py`
  - 新增 `contract.attachments` JSON 字段迁移，并合并旧 Alembic heads：`20260408_0001`、`20260624_0001`。

### 前端实现

- `frontend/src/pages/contract/components/ContractAttachmentsModal.jsx` + `.css`
  - 新增合同附件管理弹窗，支持上传、查看/下载、删除。
- `frontend/src/pages/contract/ContractListPage.jsx`
  - 合同列表新增附件数量入口。
  - 附件变化后同步更新当前列表行。
- `frontend/src/api/contract.js`
  - 新增附件列表、上传、删除、查看和下载 URL 方法。

## 会议 ASR 转写优化与问题定位

### 背景

用户反馈开发环境最新上传的会议音频在 01:44 附近漏转写：“小雪”后实际可听到“测试工具，经委，继续改开发看板的东西，行，散会吧”，但转写直接跳到“行，散会吧”；同时说话人识别也不准确。

### 调查结论

- 目标音频总时长约 150.56 秒，未触发切片，因此本次漏字不是切片合并或去重造成。
- 上传文件扩展名为 `.mp3`，但实际容器/编码为 WAV PCM（16k 单声道），需要避免扩展名与真实音频格式不一致影响 ASR。
- 多组对比测试结果：
  - WAV/raw 路径漏掉“测试工具”。
  - MP3 归一化路径能恢复“那个测试工具”。
  - 针对 111-129 秒的短窗口、增益、动态归一化、放慢语速、关闭说话人识别、模型版本/频道参数、热词上下文等组合，均未稳定识别出“经委，继续改开发看板的东西”。
  - 部分短窗口会误识别出“圆形 / 小雪 / 这个测试工具”等错位文本，因此未加入自动补扫，避免引入假内容。
- 结论：本次代码可以修复格式/时间轴/短句 speaker 问题，但豆包 ASR 原始完全漏识别的低声或快速语句，需要人工校正或接入备用 ASR（如 FunASR/Whisper/faster-whisper）才能进一步提升。

### 后端优化

- `backend/app/services/asr_service.py`
  - ASR 提交统一归一化为 16k 单声道 MP3。
  - 移除错误的 `codec/raw/rate/bits/channel` 参数，保留 `language=zh-CN`、`show_utterances=True`、`enable_speaker_info=True`。
  - 长音频切片阈值调整为 45 分钟，切片重叠调整为 12 秒。
  - 优化多切片重叠去重和 speaker alias 复用。
  - 新增局部孤立超短说话人分段平滑，减少短任务安排被误标为新 speaker。
- `backend/app/api/meeting.py`
  - 新增 `POST /api/v1/meeting/records/{meeting_id}/retranscribe`。
  - 重新转写时，新 ASR 成功后才删除并替换旧分段；失败时旧分段保留。

### 前端优化

- `frontend/src/api/meeting.js`
  - 新增 `retranscribe(id)`。
- `frontend/src/pages/meeting/MeetingDetailPage.jsx`
  - 音频区新增“重新转写”按钮。
  - 修正音频存在性判断：使用 `audio_file_name` 或 `audio_file_size`，避免依赖后端详情未返回的 `audio_stored_name`。

### 开发库验证

已对开发库会议 `f8b99cf4-e4c7-406c-8dd7-713b4c3d2a85`（标题“早会”）重新转写。目标时间段结果：
