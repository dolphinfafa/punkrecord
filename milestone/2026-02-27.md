## 1. 交易明细功能迭代

### 1.2 交易发票上传能力
- 在交易创建弹窗新增“上传发票”能力（多文件）。
- 上传文件随交易一起提交并写入 `attachments`。
- 交易列表新增“发票附件”列，显示附件份数。

## 2. 报销能力首版落地

- 新增 `CreateReimbursementModal`：
  - 支持选择主体来源账户（确定 `our_entity_id`）；
  - 支持关联合同、关联项目；
  - 支持多条费用明细（类型、金额、日期、备注）；
  - 支持每条明细上传附件。
- 报销列表支持展示费用条目数、状态、金额。

## 3. 后端与接口改造

- 交易创建接口支持接收并保存 `attachments`。
- 交易响应结构补充 `attachments`。
- 报销响应结构补充 `expense_lines`，供前端列表直接展示条目数。
- 前端 `financeApi.listTransactions` 支持 `txn_direction` 与 `account_id` 查询参数透传。

## 4. 422 问题处理

- 根因：前端请求 `page_size=200`，后端多个列表接口限制为 `le=100`，触发 422。
- 修复：将以下接口分页上限统一提升到 `200`：
  - `GET /api/v1/finance/transactions`
  - `GET /api/v1/finance/invoices`
  - `GET /api/v1/finance/reimbursements`
  - `GET /api/v1/contract/contracts`
  - `GET /api/v1/project/projects`

## 5. UI 可读性修复

## 7. 今日追加修复（财务交易明细）

### 7.1 交易类型与报销语义完善
- 新增交易类型：`收款 / 付款 / 报销`（`txn_type`）。
- 报销统一按支出处理，交易方向自动归一为 `out`。

### 7.2 报销交易对象改为员工
- 报销场景下，交易对象从“对手方”改为“员工”。
- 前端员工数据来源改为用户管理接口（`/iam/users`），并修复报销员工列表为空问题。

### 7.3 交易状态重构与可编辑
- 状态统一为：`未完成`、`已完成`、`已对账`。
- 新增交易接口支持初始化状态。
- 新增交易状态更新接口：`PATCH /api/v1/finance/transactions/{txn_id}`。
- 前端交易明细列表支持直接下拉修改已有交易状态。

### 7.4 余额计算口径修正
- 账户余额改为仅统计 `已完成/已对账` 的交易。
- `未完成` 状态交易不计入余额，报销在标记完成后才影响余额。

### 7.5 稳定性与兼容性修复
- 修复交易列表 500：
  - 根因是历史数据小写枚举值与 ORM 枚举解析不一致。
  - 通过 SQLite 启动兼容逻辑 + 数据规范化脚本统一为可识别格式。
- 修复财务页 422：
  - IAM 用户列表请求 `page_size` 从 200 调整为 100（与接口上限一致）。

### 7.6 界面可读性优化
