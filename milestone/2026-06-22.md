# 2026-06-22 Milestone

## 三项修复：会议持久化健壮性 + MCP 建 Bug + 项目任务筛选

用户生产使用中反馈三个问题，均在 `dev` 分支修复（未动 main）。

### 1. 会议总结/说话人丢失（健壮性）

**诊断**：后端持久化本身正确（dev 旧会议 summary/speaker 都在）。生产根因是**生产服务器连不上 LiteLLM**（`litellm.yios.cn` DNS 解析失败、`212.50.233.55:4000` 连接拒绝）→ 总结流为空；而代码缺陷使其仍把 `status=SUMMARIZED` 且 `summary=""` 落库，造成"已总结但空"。

**本轮修代码健壮性**（生产网络另行解决）：
- `backend/app/api/meeting.py` summarize：仅当 `full_text.strip()` 非空才落库 summary 并置 SUMMARIZED；为空/失败时不改状态、不存空总结，SSE 多发一条明确 error。
- `frontend/src/pages/meeting/MeetingDetailPage.jsx`：
  - 流式消费处理 `error` 事件（原本静默忽略导致空白），失败时清空并 alert。
  - 说话人姓名输入框 `onBlur` 也触发保存（不只回车），文案改为"失焦或回车保存"——避免编辑后未回车丢失。

> ⚠️ 生产 AI 总结要真正可用，需先解决生产到 LiteLLM 的网络连通（DNS/防火墙）。历史"空总结"会议可后续重新生成。

### 2. MCP 新增 `create_bug` 工具

`backend/app/api/mcp_server.py` 新增 `create_bug`：打 `tags=["bug"]` + `link.type="bug"`，支持 `actual_result`/`expected_result`/`reproduce_steps`，必须关联项目（project_name/project_id），assignee 缺省取调用者。转发 `POST /todo`。这样 Bug 同时出现在项目任务与「Bug 管理」（`_is_bug_todo` 判定为真）。MCP 工具数 22 → 23。

原问题：MCP `create_todo` 不会打 bug 标签，故创建的"Bug"只进项目任务、不进 Bug 管理。

### 3. 项目任务状态/负责人筛选

`frontend/src/pages/project/components/ProjectTasks.jsx`：顶部加**状态**与**负责人**两个筛选（负责人选项从任务去重生成），客户端 `useMemo` 过滤。**默认隐藏已完成(done)+已忽略(dismissed)**，可切到具体状态或"全部状态"。计数显示"过滤后/总数"。
