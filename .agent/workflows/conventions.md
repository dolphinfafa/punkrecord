# 开发规范与安全守则

> 本文档描述项目的命名规范、接口约定和变更安全规则。属于 `project-index.md` 的子文档。

---

## 1. 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 后端文件 | `snake_case` | `todo_item.py` |
| 前端组件 | `PascalCase` | `JobTitlePage.jsx` |
| JS 变量/函数 | `camelCase` | `handleSubmit` |
| API 路径 | 短横线风格 | `/job-titles` |
| 小程序页面 | `pages/<模块>/index.*` | `pages/todo/index.wxml` |
| 小程序样式 | `rpx` 单位 | `width: 200rpx` |
| 小程序用户标签 | 中文显示，JS 层映射枚举值 | `待处理` <- `pending` |

## 2. 接口响应约定

```json
// 成功
{ "data": ..., "message": "ok" }

// 错误
{ "code": 400, "message": "错误描述" }
```

## 3. 权限约定

- API 处理函数使用 `require_permission("<模块>.<read|write>")` 守护
- 当前使用的权限模块：`iam`, `todo`, `contract`, `project`, `finance`
- 权限来源双通道：角色权限 + 职位权限，取并集
- Bug 负责人修改规则：
  - PM/owner 可编辑全部计划字段
  - 任何项目成员可修改 Bug 负责人，但不能编辑其他计划字段

## 4. 认证文件访问模式

浏览器通过 `<img src>` / `<a href>` 直接发起的请求**不会**携带 `Authorization: Bearer` 头。如果后端文件下载接口需要认证，且 cookie 在开发环境（HTTP）下不可用（`secure=true`），直接 URL 会返回 401。

**正确做法**：通过 axios 请求文件（自动附带 Bearer Token），获取 blob 后用 `URL.createObjectURL()` 生成临时 URL 给 `<img>` / `<a>` 使用。示例参考 `UserListPage.jsx` 中的 `idCardBlobUrl` / `resumeBlobUrl` 实现。

注意在组件卸载时调用 `URL.revokeObjectURL()` 释放内存。

## 5. 文件编码

- 编码：UTF-8（无 BOM）
- 换行符：LF（`\n`）
- 确保 macOS、Windows、Linux 三平台正确显示

## 6. 变更安全守则

### 6.1 模块边界

- 保持模块边界清晰：模块 A 不得直接耦合模块 B 的内部实现
- 共享逻辑必须放在公共/服务层，避免跨模块复制粘贴和隐藏依赖
- 前端样式避免宽泛的全局选择器，优先使用页面级命名和共享组件

### 6.2 接口兼容性

- 后端 API 的请求/响应结构是契约，变更默认向后兼容
- 破坏性变更需要显式版本管理或前后端协调发布
- 高风险字段/枚举需在过渡期增加兼容处理

### 6.3 风险分级

每次变更需标注风险等级：

| 等级 | 场景 |
|------|------|
| **低** | 局部 UI/内容更新，无共享依赖影响 |
| **中** | 共享组件/样式/工具变更，不破坏 API 行为 |
| **高** | 跨模块行为变更、认证/权限逻辑、数据模型/枚举变更、状态机变更 |

高风险变更需更严格的审查、更广的回归范围和分阶段上线。

### 6.4 测试要求

- 单元测试：核心业务规则、校验器、状态转换
- 集成测试：跨模块 API/服务交互和持久化行为
- 端到端测试：关键用户路径（认证、任务生命周期、项目流程、财务核心流程）
- 模块 A 的变更必须运行 A 的测试 + 受影响的 B 模块路径测试
- UI 变更须验证交互：滚动、弹窗开关、提交/取消、响应式行为

### 6.5 PR/审查要求

- 每个 PR 必须标明：影响模块、风险等级、接口/数据变更、回归清单
- 涉及共享组件/样式/契约的变更需相关领域负责人审查
- 涉及 overflow/定位/布局/弹窗行为的变更应附上前后对比截图

### 6.6 数据迁移安全

- 采用非破坏性迁移序列：扩展 -> 数据迁移 -> 收缩
- 避免没有回滚或降级策略的破坏性变更
- 全量上线前验证迁移脚本和数据兼容性

### 6.7 发布与回滚

- 高影响行为变更优先使用功能开关
- 分阶段上线（先小范围），验证通过后再扩展
- 确保快速回滚路径（开关关闭、兼容降级、安全回退方案）

### 6.8 可观测性

- 发布后按模块监控关键指标：错误率、延迟、核心业务成功率
- 对变更的关键路径增加日志/链路追踪
- 发生回归时进行根因分析，并将经验转化为测试/清单/门禁
