## 任务与 Bug

| 编号 | 场景 | 预期 |
|---|---|---|
| TODO-01 | 普通待办、项目详情、开发任务、Bug、批量生成、同步、MCP 创建 | 截止日期必填；工时省略或0均成功且默认0；拒绝负数、显式null、超过两位小数和非有限值 |
| TODO-02 | 修改项目任务后打开待办，反向修改后打开项目 | ID和计划字段一致，图片与状态不丢失 |
| TODO-03 | 重复同步功能清单、重复生成同一功能任务 | 不重建任务、不重置审核与附件、不复制Bug |
| TODO-04 | 历史任务缺少日期或工时 | 日期提交前补齐；空工时按未设置显示0，不阻止验收、不参与奖励；不覆盖历史数据 |
| TODO-05 | 退回重提、审核延迟、时区跨日 | 保留最终通过版本的提交时间；按上海自然日计算延期 |
| TODO-07 | 历史待验收缺少提交时间 | 明确拒绝直接验收，允许撤回重提后正常验收；不伪造时间 |
| TODO-06 | 完成任务展开、加载更多 | 按完成时间排序，每次10项；不回归原有行为 |
| TODO-08 | 正数/0/空工时的待办卡片，编辑工时；看板/列表、我的/团队、已完成与暗色 | 正数显示绿色与“贝利任务”标识，其余普通样式；归零后恢复，恢复正数后重新显示；手机文字不溢出，不改变优先级/状态语义 |
| TODO-09 | 卡片/列表详情的描述备注为null、空串、仅一项有值、历史纯空白 | 始终有两个标题；缺失项显示暂无描述/暂无备注，有效内容和换行保留；我的/团队一致，空态不写库 |
| TODO-10 | 旧Bug仅有link.notes，顶层新备注/空串，普通任务含同名元数据；个人/团队/详情/项目Bug、完成/未完成 | 只对Bug且顶层null时兼容字符串旧备注；显式空串不复活旧内容；读取不修改数据库；非字符串不冒充正文 |
| TODO-11 | 待办编辑新增描述备注、清空、保存刷新；Bug创建/编辑后查看团队任务 | 空串清空并持久化，省略/null不变；Bug两个备注字段同步，顶层优先；桌面/手机表现一致 |
| BUG-01 | 同项目跨端标题搜索、空查询、无结果、分页 | 大小写不敏感的子串查询；百分号和下划线按字面查询 |
| BUG-02 | 筛选后刷新、翻页、浏览器前进后退 | URL保留搜索与筛选条件，结果和地址一致 |
| BUG-03 | 独立页创建、编辑、补图、预览、验收、重开 | 仍操作同一条待办；桌面/手机无页面级横向溢出 |
| BUG-04 | 共享分页0/30/31条、搜索后翻页、刷新/前进后退、加载中操作 | 每页30项；空结果1/1且双侧禁用，恰好30条无下一页；URL保留条件，加载中禁用翻页，加载结束恢复 |

## 请假与权限

| 编号 | 场景 | 预期 |
|---|---|---|
| LEAVE-01 | 创建、批准、拒绝请假 | 不创建、不改动Todo；批准时仅扣对应假期并留流水 |
| LEAVE-02 | 查看、开始、提交、验收、退回、取消历史请假待办 | 不进入普通待办和奖励队列；禁止旧状态写操作，历史记录保留 |
| LEAVE-03 | 工作日日历、半天请假、周末调休 | 按日历计算天数，半天0.5；纯休息日不可申请 |
| LEAVE-04 | 微信编号、引用、批量审批 | 明确区分请假单和任务，直接调用对应审批，不级联Todo |
| LEAVE-05 | MCP请假待审批、批准和驳回 | 使用独立请假接口，不调用普通任务审批 |
| IAM-01 | 管理员维护工资；普通员工和非管理员L0读取工资 | 管理员可维护；其他人403；公开用户、贝利和MCP响应不出现工资与换算参数 |
| IAM-02 | 非L0查别人账户、流水或调整余额 | 拒绝越权；前后端均限制 |
| IAM-03 | 用户管理旧调整与重置入口 | 不再显示；旧写接口不可绕过独立贝利流水 |
| IAM-04 | 删除无员工但有权限关联的职位；删除有员工的职位 | 前者同事务清理关联后删除，权限本身保留；后者400且数据不变，开启外键验证 |

## 贝利奖励与考勤

| 编号 | 场景 | 预期 |
|---|---|---|
| BELI-01 | 工资12000、8小时、按时P2 | 独立审核通过后240贝利；仅任务完成不发放 |
| BELI-02 | P0/P1/P2/P3与延期0/1/2/3/4/5/8天组合 | 系数分别1.2/1/1/0.8，时效1/.95/.9/.8/.6/.5/.5 |
| BELI-03 | L0审核改工时、截止日期、重要级 | 同步原任务，保留旧值和结算快照；页面不展示工资换算 |
| BELI-04 | 工资缺失、任务未验收、非L0审核 | 不发放；驳回奖励不改变任务完成状态 |
| BELI-05 | 重复审批、重开、再次验收、再次审批 | 每轮只发一次；重开冲销；历史流水不可删除 |
| BELI-06 | 手工加减贝利/假期，重复请求 | 原因必填，流水可追溯；重复请求不重复扣加，同键异参拒绝 |
| BELI-07 | 0工时任务普通/自建任务完成，随后补录正数 | 完成不入队；规则生效后完成且有可靠提交时间的任务补录后自动入队；重复保存只一条奖励、不直接发钱 |
| BELI-08 | 待审核/已驳回奖励的工时归零，再恢复正数 | 退出为excluded，保留原审核；不再可审核，伪造带正数工时的审核请求也拒绝；恢复为pending且只保留一条奖励 |
| BELI-09 | 生效前完成任务、缺少提交时间、策略未初始化 | 补录工时不自动入队；不因普通编辑追溯旧任务；已有合法审核记录不丢失 |
| BELI-10 | 已发奖改0工时、归零与发奖并发 | 已发奖必须先重开冲销；并发按任务锁串行，只能发奖或归零其一成功，不能零工时发奖 |
| ATT-01 | 启用日前会议、无记录、非工作日、L0 | 不扣款 |
| ATT-02 | 工作日早会缺席、余额不足、同日多份会议 | 非L0缺席扣500，可为负；同日名单取并集，只扣一次 |
| ATT-03 | ID绑定、旧用户名、旧唯一姓名、重名、外部人员、未发言 | 优先稳定ID；旧记录先唯一用户名再唯一姓名；同名不猜测并提示，外部姓名过滤，不将未使用speaker算出席 |
| ATT-04 | 上午已批请假、仅下午请假、事后补批 | 上午请假豁免；仅下午仍应到；补批自动冲正 |
| ATT-05 | 补录参会人、删除会议、日历调整、L0作废 | 差额更正；L0原因必填；重复重算不恢复已作废扣款 |
| ATT-06 | 服务中断、未来日期会议到期 | 定期任务补结算，重复运行不重复扣款 |
| ATT-07 | 历史员工更名、停用或升为L0 | 既有姓名快照和应到身份保持不变，不重扣已出席者、不返还原缺席扣款 |
| ATT-08 | 选择启用日前日期、重复保存员工绑定 | 明确未启用且不补扣；更正只做幂等差额，不重复扣加 |
| BELI-11 | 调整0、超范围、三位小数、NaN/Infinity；价格边界 | 0明确说明；前后端独立拒绝无效值，不变动流水；有效两位小数边界可保存 |
